# فروشگاه (Froshgah) 🏪

پیدا کردن **فروشگاه‌های پوشاک** از اینستاگرام و تلگرام — با یک سایت جستجوی فارسی روی **GitHub Pages**.

> 💡 هیچ چیزی روی کامپیوتر شما نصب نمی‌شود. پایتون و کتابخانه‌ها داخل محیط ابری گیت‌هاب (Codespaces یا Actions) اجرا می‌شوند و نتیجه به‌صورت `data/stores.json` + سایت `docs/` در همین مخزن کامیت می‌شود.

---

## راه اول: Codespaces (ساده‌ترین راه — روی همین شاخه کار می‌کند)

1. در همین صفحه گیت‌هاب، کلید **`.` (نقطه)** را بزنید (یا دکمه **Code → Codespaces → Create codespace on …**). یک VS Code کامل در مرورگر باز می‌شود؛ چند دقیقه طول می‌کشد تا پایتون و کتابخانه‌ها را خودش نصب کند.
2. **پیکربندی («مرحله ۲»):** در ترمینال همان Codespaces یک‌بار بنویسید

```bash
python -m froshgah setup
```

   سؤال‌ها یکی‌یکی می‌پرسد (نام کاربری و رمز اینستاگرام، `TG_API_ID` و `TG_API_HASH` تلگرام، توکن ربات) و همه را در فایل `.env` **همان رایانه ابری** ذخیره می‌کند. رمزها مخفی خوانده می‌شوند، در تاریخچه ترمینال نمی‌مانند و هرگز به گیت فرستاده نمی‌شوند.
   - وضعیت را بعداً با `python -m froshgah setup --check` و کلیت آماده‌به‌کاری را با `python -m froshgah doctor` ببینید.
   - جایگزین یک‌بار برای همه اجراها: در گیت‌هاب **Settings → Secrets and variables → Codespaces** رازهایی با همان نام‌ها (`IG_USERNAME`، `IG_PASSWORD`، `TG_API_ID`، `TG_API_HASH`) بسازید؛ خودکار به‌صورت متغیر محیطی در دسترس می‌شوند و `python -m froshgah setup --from-env` همان‌ها را در `.env` می‌نویسد.
   - بدون تنظیم هیچ‌کدام هم می‌شود اجرا کرد: اینستاگرام حالت ناشناس (نتایج کمتر) و تلگرام فقط پیام‌های عمومیِ همان عبارت — ولی با اکانت نتیجه خیلی بهتری می‌گیرید.
3. در ترمینال همان Codespaces یک دستور بزنید:

```bash
./scripts/collect-and-publish.sh
```

این اسکریپت جمع‌آوری می‌کند، `data/stores.json` و سایت `docs/` را می‌سازد و روی همین شاخه پوش می‌کند. (اگر پوش کرد و پیام احراز هویت آمد، یک‌بار `gh auth setup-git` را بزنید.)

می‌خواهید خودتان دستور را بنویسید؟ این معادلش است:

```bash
python -m froshgah run --ig-tags "پوشاک,مانتو" --tg-queries "فروشگاه پوشاک" --limit 25
```

برای تست خشک (بدون کامیت/پوش): `DRY_RUN=1 ./scripts/collect-and-publish.sh`

**برای تلگرام** (اختیاری): اول یک‌بار `python -m froshgah login` را در ترمینال Codespaces بزنید تا فایل `froshgah.session` ساخته شود؛ بعد `base64 -w0 froshgah.session` را بگیرید و به‌عنوان راز `TG_SESSION_B64` ذخیره کنید تا در اجراهای بعدی لازم نباشد دوباره لاگین کنید.

## راه دوم: GitHub Actions (اجرای خودکار، بدون باز کردن Codespaces)

فایل `.github/workflows/collect.yml` همان کار بالا را روی سرور گیت‌هاب انجام می‌دهد. **مرحله‌به‌مرحله:**

1. **Secrets:** Settings → **Secrets and variables → Actions** → *New repository secret*. این نام‌ها را با مقدارشان بسازید: `IG_USERNAME`، `IG_PASSWORD`، `TG_API_ID`، `TG_API_HASH`، `TG_SESSION_B64`. (فقط اگر ربات تلگرام را هم می‌خواهید: `TELEGRAM_BOT_TOKEN` و `TELEGRAM_OWNER_ID`.)
2. **تب Actions:** بالای همین مخزن تب **Actions** را باز کنید ← از ستون سمت چپ workflow **«collect»** را انتخاب کنید ← دکمه سبز **Run workflow** (سمت راست بالا) باز می‌شود ← فیلدها را پر کنید (`ig_tags` هشتگ‌ها با کاما، `tg_queries` عبارت‌های تلگرام با کاما، `limit` تعداد) ← **Run workflow**. بعد به همان لیست برگردید و روی اجرای جدید کلیک کنید تا لاگ را ببینید؛ وقتی تمام شد، یک کامیت با پیام `data: …` روی شاخه نشسته است و سایت به‌روز شده.
   - ⚠️ **یک محدودیت گیت‌هاب:** دکمه «Run workflow» فقط برای workflowای ظاهر می‌شود که فایلش در **شاخه پیش‌فرض (main)** وجود داشته باشد. تا وقتی این شاخه ادغام نشود، این راه در دسترس نیست — فعلاً همان **راه اول (Codespaces)** را استفاده کنید.
   - اگر هم خواستید بدون ادغام تستش کنید، من (یا شما با `gh`) می‌توانیم با API آن را روی این شاخه اجرا کنیم؛ ولی چون دسترسی توکن من برای `actions:write` بسته است، این کار را خودتان در مرورگر باید انجام دهید.
3. برای **اجرای خودکار هر روز** انتهای همان فایل، چهار خط `schedule` را از کامنت خارج کنید (باز هم نیاز به داشتن فایل روی main دارد).

## سایت (GitHub Pages)

Pages روی این مخزن از شاخه کاری، پوشه `/docs` فعال است: **https://aminchat.github.io/Froshgah/**

هر بار که `data/stores.json` و `docs/` به‌روز شوند، سایت خودش بازسازی می‌شود (۱ تا ۲ دقیقه). در سایت می‌توانید:

- جستجوی آزاد (فارسی نرمال‌سازی می‌شود: ی/ی، ک/ک، نیم‌فاصله، ارقام فارسی، تلفن با ۰۹۱… یا ۹۱۲…)
- فیلتر **منبع** (اینستاگرام/تلگرام)، **شهر**، **دسته**، و «فقط شماره‌دار»
- با یک کلیک روی شماره، کپی شود؛ لینک پیج/کانال/سایت مستقیم باز شود
- کلید `/` برای پرش به کادر جستجو؛ لینک قابل اشتراک با `?q=...&src=instagram`

اگر روزی خواستید مسیر انتشار را عوض کنید: Settings → **Pages** → Source: *Deploy from a branch* → شاخه و `/docs`.

## راه سوم: سرویس وب روی Vercel (لاگین و فرم در خود صفحه)

اگر می‌خواهید مثل یک اپ واقعی باشد: آدرس ثابت، **صفحه ورود**، و دکمه «جمع‌آوری» که همان‌جا نام کاربری/رمز اینستاگرام را می‌گیرد — سرویسش `api/index.js` است (Node.js بدون هیچ کتابخانه‌ای) و فایل‌های سایتش از `public/` سرو می‌شوند.

**چطور کار می‌کند:**

```
مرورگر شما ──▶ Vercel (قفل لاگین + جستجو)        ──▶ داده را از مخزن می‌خواند
                    │
                    └─▶ GitHub Actions (موتور پایتون: instaloader + Telethon)
                              └─▶ data/stores.json را کامیت می‌کند ──▶ Vercel و Pages هر دو به‌روز می‌شوند
```

- رمز اینستاگرام/تلگرام **جایی ذخیره نمی‌شود**: سرور Vercel آن را با AES-256-GCM رمزنگاری می‌کند، به‌عنوان `payload` به Actions می‌دهد، و پایتون فقط در حافظه همان اجرا بازش می‌کند. در صفحه اجراهای Actions فقط متن رمزنگاری‌شده دیده می‌شود.
- Vercel اسکرپ نمی‌کند (محدودیت زمان Functionها)؛ فقط لاگین، جستجو و فرمان اجرا را انجام می‌دهد. کار سنگین همان‌جا است که پایتون و ۳۰ دقیقه زمان دارد.
- برای اینکه مخزن خصوصی بماند هم همین معماری کار می‌کند: سرور با `GITHUB_TOKEN` داده را از API می‌خواند (نیازی به عمومی‌بودن مخزن نیست).

**متغیرهای محیطی Vercel (Project → Settings → Environment Variables):**

| نام | توضیح |
|---|---|
| `SITE_PASSWORD` | رمزی که در صفحه ورود می‌زنید (خودتان یک عبارت بلند بسازید) |
| `APP_SECRET` | کلید رمزنگاری بارِ فرم و امضای کوکی؛ **باید** در GitHub هم به‌عنوان Secret با همین مقدار باشد |
| `GITHUB_TOKEN` | Fine-grained PAT با همین دو سطح: **Actions: Read and write** (دکمه جمع‌آوری + نمایش وضعیت اجرا) و **Contents: Read-only** (خواندن داده، لازمِ مخزن خصوصی) |
| `GITHUB_REPO` | **اختیاری** — مثل `aminchat/Froshgah`؛ پیش‌فرضش داخل `api/index.js` است، چون نام مخزن راز نیست |
| `GITHUB_REF` | **اختیاری** — شاخه‌ای که داده در آن است (پیش‌فرض `arena/e5aae2ae-froshgah`). بعد از ادغام روی `main` این را `main` بگذارید |
| `WORKFLOW_FILE` | پیش‌فرض `collect.yml` |
| `ALLOW_PUBLIC_DATA` | فقط اگر خواستید سایت بدون لاگین باز باشد: `1` |

**سمت گیت‌هاب:** یک Actions Secret به نام `APP_SECRET` با همان مقدار Vercel بسازید. دکمه «جمع‌آوری از صفحه» فقط وقتی کار می‌کند که فایل `collect.yml` روی `GITHUB_REF` باشد (گیت‌هاب اجرای workflow را از شاخه‌های دیگر بیرون از default branch نمی‌پذیرد؛ اگر ۴۰۴ گرفتید، یعنی همان قانون).

**این رشته‌ها را کجا نگه دارم؟** یک کپی در یک password manager (Bitwarden/1Password/Note) بگذارید — نه در مخزن، نه در چت. نکات:

- `SITE_PASSWORD` را واقعاً لازم دارید (هر بار ورود). اگر گمش کردید چیزی از دست نمی‌رود: در Vercel یک مقدار تازه بگذارید و Redeploy کنید.
- `APP_SECRET` جایی داده‌ها را قفل نمی‌کند (ما چیزی ذخیره نمی‌کنیم)، پس اگر گم شود هیچ داده‌ای از بین نمی‌رود؛ فقط باید در **هر دو** طرف (Vercel و GitHub Secrets) با یک مقدار تازه یکی‌شده عوضش کنید.
- اگر دو طرف یکی نباشند، خطای «بازکردن بار پنل وب ناموفق بود» می‌گیرید — درمانش فقط همین است که هر دو را با یک مقدار تازه ست کنید.
- `GITHUB_TOKEN` را هم لازم نیست جایی نگه دارید: اگر گم/منقضی/لو رفت، یکی تازه بسازید، در Vercel → Environment Variables مقدار تازه بگذارید، Redeploy کنید و توکن قدیمی را در گیت‌هاب Delete کنید. (توکن گم‌شده هیچ داده‌ای را قفل نکرده که بخواهید پس بیاوریدش.)
- چون مقدارهای Sensitive در Vercel دوباره نمایش داده نمی‌شوند، برای اینکه «درست تایپ کردم یا نه» را بفهمید مقدار را دستی تایپ نکنید: با `python -m froshgah secret` بسازید و کپی/پیست کنید، بعد آدرس `/api/config` را باز کنید — اگر `{"ok": true` بود، همه‌چیز سر جایش است.

**ساخت رشته‌های محرمانه:** با `python -m froshgah secret` (یا `--count 2` برای دو رشته) یک مقدار تصادفی بسازید — یکی برای `APP_SECRET` و یکی برای `SITE_PASSWORD`. این مقدارها را در چت، ایمیل یا تیکت پشتیبانی ننویسید: بارِ فرمِ جمع‌آوری به‌صورت رمزنگاری‌شده در صفحه اجرای Actions دیده می‌شود، پس اگر کلیدش جایی عمومی بماند، رمز اینستاگرام شما هم قابل بازکردن است. هر ۶ ماه یک‌بار چرخشش خوب است (هم در Vercel هم در GitHub Secrets، با هم).

**تست محلی:**

```bash
node tools/serve-web.js             # رمز تصادفی می‌سازد و چاپ می‌کند → http://127.0.0.1:8000
node tests/web_smoke.mjs             # تست یکپارچه سرویس (۱۴ بررسی)
```

**دیپلوی (۴ کار در Vercel):**

1. **Add New… → Project → Import** مخزن `Froshgah` را انتخاب کنید (اگر مخزن در لیست نبود، از *GitHub App → Configure* دسترسی `Froshgah` را بدهید).
2. وقتی **Root Directory** را پرسید، همان **`Froshgah (root)`** را انتخاب کنید؛ Build Command، Install Command و Output Directory را دست نزنید (فایل `vercel.json` ریشه مخزن همه‌چیز را تنظیم می‌کند: خروجی = `public/`، تابع = `api/index.js`).
3. **Environment Variables** همان جدول بالا را پر کنید (سه تا لازم است: `APP_SECRET`، `SITE_PASSWORD`، `GITHUB_TOKEN`). نوع هر سه را **Sensitive / Encrypted** بگذارید و `GITHUB_REPO`/`GITHUB_REF` را اگر ساختید **Plain** بگذارید — متغیرهای Sensitive بعداً در داشبورد خوانده نمی‌شوند، پس نباید چیزی که برای عیب‌یابی به آن نگاه می‌کنید داخلشان باشد.
4. چون فعلاً همه‌چیز روی شاخه کاری است و `main` دست‌نخورده: در *Project Settings → Git → Production Branch* را روی `arena/e5aae2ae-froshgah` بگذارید (وگرنه فقط preview ساخته می‌شود). اگر preview باز نشد، *Settings → Deployment Protection* را برای این پروژه خاموش کنید.

پوشه `public/` تولیدی است و در مخزن کامیت شده؛ هر بار که داده عوض می‌شود با `python -m froshgah site` (که `docs/` و `public/` هر دو را می‌سازد) یا همان `scripts/collect-and-publish.sh` بازسازی می‌شود. دیپلوی از گیت، هر پوش را خودش به‌روز می‌کند.

## ربات تلگرام (اختیاری)

ربات به یک سرویس **همیشه‌روشن** نیاز دارد؛ گیت‌هاب جای آن نیست (Actions کارهای کوتاه اجرا می‌کند، Pages فقط فایل ایستا می‌دهد). اگر خواستید، در همان Codespaces بزنید `python -m froshgah bot` (تا پنجره باز است کار می‌کند) یا روی یک VPS ارزان. دستورات: `/search`، `/latest`، `/stats`، `/collect_ig`، `/collect_tg` (دو تای آخر فقط برای مدیر).

## اجرا روی کامپیوتر خودتان (برای توسعه)

```bash
pip install -r requirements-dev.txt
cp .env.example .env
python -m froshgah init
python -m froshgah run --ig-tags "پوشاک" --tg-queries "فروشگاه پوشاک"
python -m froshgah search "مانتو تهران"
python -m froshgah site && (cd docs && python -m http.server 8000)
pytest -q
```

سایر فرمان‌ها: `setup` و `doctor`، `collect ig --hashtag … [--bios]`، `collect tg "…" [--no-deep]`، `export`، `latest`، `stats`، `login`، `bot`.

## رمزها را کجا بگذارم؟ 🔐

- **هیچ‌جا این‌ها را در چت، ایمیل یا تیکت پشتیبانی ننویسید** — نه برای من، نه برای هیچ‌کس دیگر.
- سایت `https://<کاربر>.github.io/Froshgah/` **هیچ فرم ورودی ندارد** و هیچ‌وقت نام کاربری یا رمز شما را نمی‌پرسد؛ فقط نتایج ذخیره‌شده را نشان می‌دهد. اگر چنین درخواستی دیدید، کلاهبرداری است.
- جای رمزها فقط یکی از این دو است: فایل `.env` داخل محیط اجرا (Codespaces یا VPS)، یا **Settings → Secrets** همین مخزن.
- برای تلگرام «رمز» لازم نیست: `TG_API_ID` و `TG_API_HASH` شناسه‌ی برنامه‌اند و در `python -m froshgah login` فقط شماره موبایل و کد یک‌بارمصرف وارد می‌شود.
- برای اینستاگرام هم می‌توانید اصلاً رمز ندهید (حالت ناشناس). اگر اکانت می‌دهید، یک اکانت ثانویه بهتر از اکانت اصلی‌تان است؛ این روش غیررسمی است و امکان محدودشدن همان اکانت وجود دارد.

## محدودیت‌ها ⚠️

- **اینستاگرام API رسمی برای جستجو ندارد**؛ `instaloader` غیررسمی است و IPهای دیتاسنتر (گیت‌هاب) را زودتر محدود می‌کند. اگر `429` یا «private profile» دیدید: `limit` را کم کنید، `REQUEST_DELAY` را بالا ببرید، یا `runs-on: self-hosted` را روی یک VPS خودتان امتحان کنید.
- جستجوی سراسری تلگرام با اکانت کاربری انجام می‌شود و فقط کانال/گروه‌های در دسترس شما را می‌بیند.
- فقط داده‌های عمومی خوانده می‌شود. اسپم و تماس دسته‌جمعی ممنوع؛ مسئولیت رعایت ToS و قوانین محلی با استفاده‌کننده است.
- رایگان بودن: برای مخزن public، Actions و Pages رایگان‌اند؛ Codespaces ماهانه ۱۲۰ ساعت رایگان دارد.

## ساختار پروژه

```
froshgah/            موتور پایتون (استخراج، دیتابیس، جستجو، ربات)
├── run.py           یک اجرای کامل: ادغام ← جمع‌آوری ← JSON ← سایت
├── export.py        دیتابیس ↔ data/stores.json (حافظه‌ی ادامه‌دار پروژه)
├── site.py          ساخت پوشه docs/ از روی web/
├── extract.py       استخراج تلفن/آیدی/شهر/دسته از متن
├── normalize.py     نرمال‌سازی فارسی
├── db.py            SQLite + جستجو و ادغام
├── bot.py / cli.py  ربات تلگرام و خط فرمان
└── collectors/      instagram.py (instaloader) و telegram.py (Telethon)
web/                 سایت ایستا (HTML/CSS/JS خالص، جستجو سمت مرورگر) — منبع هر دو نسخه
```
